# Agent-side analysis (Claude, 2026-07-05)

Written by the agent the tooling targets, after reviewing: the full MCP tool
surface (`AgdaMcp/Tools.hs`, `AgdaMcp/Query.hs`, `AgdaInteract/Tools.hs`), the
plugin layer (`plugin/SKILL.md`, agents, README), the VerinaAgda A/B benchmark
results, and Jolteon-FastBFT as the mature real-world consumer (~74k lines of
Agda, hole-free liveness proof, deep agda-explore integration).

## Verdict: is the MCP server a good idea?

**Yes — but the verdict splits in two, and neither half is the headline.**

- **Write-side bridge: unambiguously the right architecture.** A warm,
  stateful `agda --interaction-json` session across tool calls is something no
  CLI invocation can provide. On a Jolteon-sized project a cold reload costs
  minutes; a warm `check` costs seconds — the difference between an agent
  iterating on a proof ~20 times per session and ~3 times. The surrounding
  design (diff-first / no-write default, zero-axiom guard rejecting
  `postulate` before Agda sees it, atomic batching via `give_many` /
  `construct`, localized type errors with the file untouched) is genuinely
  well-tuned for agents. Jolteon is the existence proof: a hole-free liveness
  theorem closed with three MCP-wired agents.

- **Read-side: the value is the *daemon*, not the MCP protocol.** What the
  agent actually benefits from is freshness management (`ensureFresh`,
  watcher, `warmStart`, the `# stale:` footer) — never silently reasoning over
  a stale graph. The MCP wrapper costs real context (~33 tool schemas with
  60–150-word descriptions in every session) and only works in MCP-capable
  harnesses. The same point queries served additionally by a thin CLI would be
  scriptable, pipeable, and usable from CI. Complement, not replacement.

- **The dominant finding is about routing, not capability.** The VerinaAgda
  A/B experiment showed with-MCP agents made **0 MCP calls in 262 sessions**
  until the harness explicitly pointed at the tools. Agents have `grep` and
  `Read` in their muscle memory from training; a better tool sitting in a
  catalog does not change behavior by itself. Every capability investment
  below should be matched by a routing investment (hooks, skill triggers,
  consumer-repo CLAUDE.md).

### What is already right — do not regress

Bounded, ranked plain-text outputs with `…and N more` tails; three-tier name
resolution (FQN → unique suffix → near-match with an `(auto-resolved …)`
breadcrumb); "did you mean" on every unresolved name; empty results phrased as
actionable statements ("Changing `X` is safe: nothing depends on it");
next-step hints naming the tool to try; the stale footer; diff-first mutators;
atomic batching; the zero-axiom guard with self-explanatory rejections. This
is well above the median MCP server. Keep all of it.

## 1. The hook layer: PreToolUse / PostToolUse

> ✅ **Shipped 2026-07-05** — both hooks (`plugin/hooks/`) and the Phase-2
> `--control-port` endpoint (`AgdaMcp.Control`) are implemented and verified.
> The design below is preserved as the rationale; the code matches it.

This is the highest-leverage change and it requires no new server capability
in its first phase. The two chronic agent failure modes in Agda work are:

- **drift** — making several text edits before typechecking, then facing a
  pile of confounded errors (PostToolUse fixes this);
- **habit** — reaching for `grep` when the elaborated graph answers the
  question better (PreToolUse fixes this).

Both are properties of the *harness*, not the agent's knowledge: the skill
already says "prefer these tools over grep" and "check after editing", but
instructions read once compete with training priors on every single decision.
Hooks fire *at the decision point*, every time, deterministically.

### Mechanics (verified against current Claude Code docs, July 2026)

- Plugins ship hooks in `hooks/hooks.json` at the plugin root — same schema as
  `.claude/settings.json` hooks; `${CLAUDE_PLUGIN_ROOT}` resolves in commands.
  They merge with user/project hooks and are active only while the plugin is
  enabled. **Hooks also fire in headless `claude -p` runs**, so the effect is
  measurable in VerinaAgda (§8).
- **PreToolUse** receives `{session_id, cwd, tool_name, tool_input, …}` on
  stdin. To block: exit 2 (stderr becomes feedback to Claude) or exit 0 with
  `{"hookSpecificOutput": {"hookEventName": "PreToolUse",
  "permissionDecision": "deny", "permissionDecisionReason": "…"}}`. The reason
  is shown to Claude. `"allow"` + `"additionalContext"` is the softer variant.
- **PostToolUse** additionally receives the tool's output. It *cannot* block
  (the tool already ran); exit 2 feeds stderr to Claude as context, or exit 0
  with `{"hookSpecificOutput": {"hookEventName": "PostToolUse",
  "additionalContext": "…"}}` injects context cleanly.
- **Matchers** match `tool_name`: `"Edit|Write"` is exact-alternation;
  anything with regex metacharacters is a JS regex (`"mcp__agda-explore__.*"`
  works). Per-hook `timeout` (seconds) is configurable.

### PostToolUse: auto-check after every Agda edit

**Phase 1 — nudge (ship immediately, zero server changes).** After any
`Edit`/`Write` touching `*.agda` / `*.lagda.md`, inject a reminder to validate
via the warm bridge. This converts the skill's "good habit" into a
per-edit signal.

`plugin/hooks/hooks.json`:

```json
{
  "description": "agda-explore loop-closing hooks",
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [
          { "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/hooks/post-agda-edit.sh",
            "timeout": 120 } ] }
    ],
    "PreToolUse": [
      { "matcher": "Grep",
        "hooks": [
          { "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/hooks/pre-grep-route.sh",
            "timeout": 10 } ] }
    ]
  }
}
```

`plugin/hooks/post-agda-edit.sh` (Phase 1 body, with the Phase 2 upgrade
already wired in):

```bash
#!/usr/bin/env bash
set -u
input=$(cat)
file=$(jq -r '.tool_input.file_path // empty' <<<"$input")
case "$file" in
  *.agda|*.lagda.md) ;;
  *) exit 0 ;;
esac
cwd=$(jq -r '.cwd' <<<"$input")
port_file="$cwd/.agda-explore/control-port"
if [[ -r "$port_file" ]]; then
  # Phase 2: real warm check via the daemon's control endpoint.
  result=$(curl -sf --max-time 90 --get \
             "http://127.0.0.1:$(cat "$port_file")/check" \
             --data-urlencode "file=$file") \
    && { jq -n --arg ctx "$result" \
           '{hookSpecificOutput:{hookEventName:"PostToolUse",
             additionalContext:$ctx}}'; exit 0; }
fi
# Phase 1 fallback: nudge only.
jq -n --arg f "$file" '{hookSpecificOutput:{hookEventName:"PostToolUse",
  additionalContext:("You edited \($f) as text. Validate it now with the \
agda-explore bridge before further edits: `check file=\($f)` (warm session; \
returns ✓/✗ plus every error, warning and open goal). Do not run `agda` \
directly — the bridge session is already warm.")}}'
exit 0
```

**Phase 2 — real warm check via a daemon side channel.** The MCP server's
stdio is owned by Claude Code, so an external hook process cannot call MCP
tools. To let the hook run the *actual* check and inject real diagnostics:

- Add a `--control-port N` flag / `control-port:` YAML key (default **off**),
  serving a minimal localhost HTTP endpoint `GET /check?file=…` that runs the
  same code path as the `check` tool and returns its text verdict.
- **Layering:** do *not* put this in `AgdaMcp.Inspect` — Inspect deliberately
  imports no project module (so `State` can hold the hub without a cycle).
  Create a small `AgdaMcp/Control.hs` with the same hand-rolled-HTTP pattern,
  and have `MainMcp` pass it a `Text -> IO Text` callback built from the same
  runner `tools/call` dispatches to. No import cycle, no new dependency.
- **Concurrency:** reuse the per-session serialization the tool path already
  has. If the session is busy (agent mid-call), return 503; the hook then
  falls back to the Phase 1 nudge. Never queue behind a long-running load —
  hooks have timeouts.
- **Discovery:** on startup write the bound port to
  `<project>/.agda-explore/control-port`; remove it on shutdown. The hook's
  existence check doubles as the feature gate.
- **Security:** bind 127.0.0.1 only, like the inspector. `/check` reads disk
  and mutates only session state, never files.

**Pitfalls to design around:**

- *Noise:* only fire on Agda files (the `case` guard); consider suppressing
  repeat nudges for the same file within one turn (sentinel keyed on
  `session_id` + file + a short TTL) so a multi-file refactor is not spammed.
- *The 503/busy path must be silent-degrade*, never an error — a failed hook
  that prints garbage erodes the agent's trust in all hooks.
- *Timeouts:* `check` on a heavy module can exceed 90s (Jolteon proofs run
  with huge memory limits). Keep the curl `--max-time` below the hook
  `timeout`, and let the fallback nudge fire instead of a truncated result.
- *Do not `decision: block`* on a failed check — a failing intermediate state
  is often intentional mid-refactor. Inject diagnostics; let the agent decide.

### PreToolUse: routing structural greps to the graph

Goal: at the moment the agent reaches for `Grep` in an Agda project, tell it
once — with the concrete tool mapping — that the elaborated graph answers
structural questions better, then get out of the way.

`plugin/hooks/pre-grep-route.sh`:

```bash
#!/usr/bin/env bash
set -u
input=$(cat)
sid=$(jq -r '.session_id' <<<"$input")
cwd=$(jq -r '.cwd' <<<"$input")
filter=$(jq -r '[.tool_input.glob // empty, .tool_input.path // empty,
                 .tool_input.type // empty] | join(" ")' <<<"$input")

# Fire when the grep explicitly targets Agda sources, or when we are in an
# agda-explore project and no non-Agda filter narrows the search away.
agda_project=false
[[ -f "$cwd/.agda-explore.yml" || -f "$cwd/.agda-explore.yaml" ]] && agda_project=true
case "$filter" in
  *agda*) ;;                                   # explicitly Agda-targeted
  *.hs*|*.rs*|*.md*|*.py*|*.json*) exit 0 ;;   # explicitly not Agda
  *) $agda_project || exit 0 ;;
esac

# Once per session: deny with the mapping; afterwards stay silent.
sentinel="${TMPDIR:-/tmp}/agda-explore-route-$sid"
[[ -e "$sentinel" ]] && exit 0
touch "$sentinel"
jq -n '{hookSpecificOutput:{hookEventName:"PreToolUse",
  permissionDecision:"deny",
  permissionDecisionReason:"This project serves an elaborated Agda dependency \
graph via the agda-explore MCP; structural questions are better answered \
there (grep misses with-abstractions and instance references, and re-reads \
every file): definition site -> locate; name substring or list by kind/state \
-> search; who uses X -> callers; what X uses -> callees; type -> type_of; \
lemma matching a goal -> find_lemma. If you genuinely need a TEXT search \
(prose, comments, error strings), re-run the same grep now — it will be \
allowed."}}'
exit 0
```

**Design decisions and pitfalls:**

- **Deny exactly once per session** (the sentinel). A permanent deny would be
  hostile — text searches over `.lagda.md` prose are legitimate, and the
  second attempt sails through. This is "one well-timed lesson", not a wall.
- **Match `Grep` only, not `Glob`.** File enumeration (`**/*.agda`) has no MCP
  replacement; blocking it would be pure friction.
- **Optional extension:** a second matcher on `Bash` inspecting
  `.tool_input.command` for `grep|rg .*\.agda` catches shell-level greps; on
  Claude Code ≥ 2.1.85 the per-hook `if` field can pre-filter this without
  spawning the script. Ship it after the Grep hook proves itself.
- The consumer repo can also add project-local hooks in
  `.claude/settings.json` (they merge; most restrictive PreToolUse decision
  wins) — e.g. Jolteon could deny `agda <file>` in favor of `check`.

## 2. Stdlib graph federation

**The gap:** `buildBaseArgs` runs `agda-deps` with `--no-externals`, so the
graph holds only project-local definitions. `search toWitness` → "No
definitions matching" even when the project imports stdlib everywhere. For a
proving agent, "does stdlib already have this lemma?" is the single most
frequent question, and today the answer is guess-and-hope. (Already noted in
TODO.md; this is the implementation shape.)

**Phase 0 — works today, no code:** prebuild a stdlib graph once
(`agda-deps <seed> -o <dir> --format=json --json-mode=expanded
--with-signatures`, *without* `--no-externals`, where the seed imports the
stdlib surface — the VerinaAgda setup got ~7,185 defs / 9.5 MB / ~5 s from a
19-module seed) and register a *second* read-only server in `.mcp.json` with
`--graph <that>/deps.json`. Works, but duplicates 14 tool schemas in context
and makes the agent choose a server per query. Treat as a stopgap only.

**Phase 1 — overlay graphs in one daemon (the real design):**

1. **Build script.** `scripts/build-stdlib-graph.sh`: generates a seed module
   (import stdlib's `Everything`, or a curated common-modules list for a
   smaller graph), runs `agda-deps` as above, writes to
   `~/.cache/agda-explore/stdlib-<agda-version>-<stdlib-version>/deps.json`.
   Key the cache on stdlib version *and* producer `nodeKeyVersion`.
2. **Config.** `--overlay-graph PATH` (repeatable) / `overlay-graphs:` YAML
   list. Overlays are static: decode once at startup into `ssOverlays`,
   validate `v` and `nodeKeyVersion` exactly like the main path, and on
   mismatch **warn and skip the overlay** — never take the daemon down for a
   stale cache.
3. **Merge.** On every snapshot commit (initial load, `warmStart`, hot-swap),
   union the live project graph with the overlays before building the
   `Index`. `AgdaGraph.Union` already unions per-entry expanded graphs for
   multi-entry mode — reuse it; confirm its duplicate-key policy and make
   *project defs win* on collision.
4. **Origin tagging.** Carry a per-definition origin (project vs overlay
   name); render it as a suffix in `locate`/`search`/`find_lemma` output
   (e.g. `[external: agda-stdlib]`). This tells the agent "this needs an
   `open import` before use" — and `new_module`'s import resolution, which
   already reads the index, starts resolving stdlib imports for free.
5. **Honest scope note.** The project graph was built with `--no-externals`,
   so there are **no edges across the boundary**: `search` / `type_of` /
   `find_lemma` / `similar_types` gain stdlib coverage; `callers` / `impact` /
   `path` / `roots` do not cross into it. Say so in the tool descriptions.
   (The deeper fix — a producer flag keeping external edges as dangling
   references — belongs in the agda-deps repo; note it there.)
6. **Cost.** Even a full-`Everything` stdlib graph (~tens of MB JSON) decodes
   once and adds little against the current ~456 MiB resident set. Memory was
   already fought for once (see the RAM-optimization pass); measure before
   and after with the same methodology.
7. **Testing.** A miniature overlay fixture beside `test/deps.json`; golden
   outputs for `search` with and without the overlay; a nodeKeyVersion-skew
   fixture asserting the warn-and-skip path.

## 3. Orientation bundles: `brief` and `goal_brief`

**The gap:** every tool call is a full model turn. An agent starting work on a
definition *always* runs the same opening sequence — `locate`, `type_of`,
`callers`, `callees` (and on a hole: `goal_type`, `goal_context`, `lemmas`).
That is 3–4 turns of latency and context for what is conceptually one
question: "brief me on X." The write side already embraces batching
(`give_many`, `construct`); the read side deserves the same.

**Implementation guideline:**

1. **`brief name=X`** (read side, `AgdaMcp/Tools.hs` + `Query.hs`): compose
   the existing pure query functions — the `locate` block, the `type_of`
   signature, direct `callers` and `callees` capped at ~10 each with their
   existing `…and N more` tails, `similar_bodies` top-3 — into one sectioned
   text block. Target ≤ 1,500 tokens worst-case. No new analysis code: this
   is pure composition of already-tested renderers, so reuse the same
   `resolveDefNote` path (suffix resolution + did-you-mean come along free).
2. **`goal_brief goal=gN`** (write side, `AgdaInteract/Tools.hs`): compose
   `goal_type` + `goal_context` + `lemmas` top-5 against the already-loaded
   session. `lemmas` already reads the live goal type — this is one runner
   calling three existing runners.
3. **Schemas:** one required param each (`name` / `goal`), plus an optional
   `limit`. Resist adding filters — the point is a fixed-shape opener; the
   filtered tools remain for follow-ups.
4. **Skill update:** change the "Good habits" opener to "lead with `brief`";
   demote the individual tools to follow-up refinement. This is also where
   the tool count concern (§4) partially self-resolves: a good bundle makes
   several fine-grained calls rarer without removing them.
5. **Testing:** golden `brief` output on `test/deps.json`; assert the token
   ceiling with a worst-case high-degree node.

## 4. Context economy: trim the catalog

**The gap:** 33 tools whose descriptions run 60–150 words each (14 read-side
+ 19 write-side; the 2026-07-05 pass added `auto_all`). The
`tools/list` payload is loaded into *every* session of any project with the
plugin enabled — including sessions that never touch Agda. The information is
good; its *location* is wrong: depth belongs in the skill (loaded only when
Agda work starts), not the always-on catalog.

**Implementation guideline:**

1. **Measure first.** Script it:
   `printf '…initialize…\n…tools/list…\n' | agda-explore --graph test/deps.json | wc -c`
   — record the baseline in the commit message. Target ≥ 40% reduction.
2. **Rewrite every description to ≤ 2 sentences:** one for what question it
   answers, one routing cue (keep the "Use instead of grepping…" liners —
   they are routing signals, the thing §1 shows actually matters). Move
   parameter semantics into the JSON-schema `description` of each property
   (paid only when the tool is considered) and the worked recipes (the
   `roots` axiom-audit recipe, `find_lemma`'s two-mode contract) into
   `SKILL.md`, which already has the structure for them.
3. **Do not rename tools or change schemas.** Jolteon's allow-lists
   (`mcp__agda-explore__*`) and its agents' accumulated memory files refer to
   current names; renames silently orphan them.
4. **Deduplicate repeated boilerplate in *outputs* too:** the "apply this
   diff and then call `load`…" sentence recurs on every mutator result.
   Keep it (a stateless server cannot know what the agent has learned) but
   cut it to one clause; the skill carries the full contract.
5. **Overlap pruning (later, measured):** the likeliest agent confusion pairs
   are `find_lemma` vs `lemmas` vs `similar_types`, and `impact` vs
   transitive `callers`. Before merging anything, instrument which tools
   agents actually call (the inspector feed already sees every call — log a
   histogram) and let usage data drive it. ✅ *The histogram shipped
   2026-07-05: `handleCall` counts every dispatch (`ssToolCounts`) and
   `status` renders a per-run tool-usage table. The description-trimming and
   overlap-pruning it was meant to inform remain open.*

## 5. Machine-readable results: `format: json`

**The gap:** every tool returns prose (`Either Text Text` →
`content:[{type:"text"}]`). Agents parse prose fine for point queries, but
list-shaped results (`search`, `callers`, `unused`) invite post-processing —
"which of these callers are in `Properties/`?" — that today costs another
round trip or error-prone mental filtering. Structured output also feeds §7.

**Implementation guideline:**

1. **Scope tightly:** `search`, `callers`/`callees`, `unused` first. `locate`
   and `type_of` are read-once — leave them prose.
2. **Refactor shape:** the list renderers in `Query.hs` currently interleave
   computation and formatting. Split each into (a) a producer returning typed
   rows and (b) the existing text renderer over those rows; add a JSON
   renderer beside it. Byte-identical text output before/after is the
   regression test (the determinism discipline this repo already lives by).
3. **Envelope:** `{"tool": "callers", "query": {...echoed args...},
   "total": N, "shown": M, "items": [...]}` — `total`/`shown` preserve the
   `…and N more` affordance that keeps context bounded.
4. **Transport:** emit JSON as the text content (simplest, works everywhere).
   MCP's `structuredContent` result field is the principled upgrade later;
   it touches `Rpc.hs`'s result encoding, so do it as its own change.
5. **Default stays `text`.** Prose with did-you-mean is the better default
   for a reasoning agent; `format: json` is opt-in for scripting.

## 6. Closure-coverage warning (the barrel footgun)

**The gap:** Jolteon's CLAUDE.md warns that a proof root not added to a barrel
is *invisible to the MCP*. From the agent side this failure is silent and
poisonous: `search` says "No definitions matching", the agent concludes the
definition does not exist, and reasons onward from a false premise. An agent
cannot distinguish "not in the project" from "not in any entry's closure"
unless the server says so.

**Implementation guideline:**

1. **Compute per snapshot** (`AgdaMcp/State.hs`, at commit time): walk the
   include dirs for `*.agda` / `*.lagda.md` (skip hidden dirs,
   `.agda-explore/`, `dist-*`); diff against the set of files that appear in
   any definition's location in the committed graph. Store count + a few
   sample paths in the snapshot (e.g. `ssOrphanFiles`). A few hundred files —
   trivially cheap next to a graph decode; recompute only on commit.
2. **Surface in `status`:** a line like
   `⚠ 12 source files under agda-src are outside every entry's closure
   (e.g. Extras/NewAccount/Lemma7.agda) — add them to a barrel or entry.`
3. **Surface on empty `search`/`locate`:** append a one-line note *only when
   the count is nonzero and the result is empty* — exactly the moment the
   agent is about to draw the wrong conclusion. Follows the established
   next-step-hint pattern (`notFound` / `notInGraph`).
4. **Config escape hatch:** `coverage-ignore:` globs in `.agda-explore.yml`
   for intentionally-orphaned files (scratch, unsafe helpers, `papers/`), so
   the warning stays high-signal.

## 7. Thin CLI client ("code mode")

**The gap:** the read-side queries are locked behind MCP. A CLI makes them
composable (`| jq`, loops, scripts), usable from CI and non-MCP harnesses,
and enables the code-mode pattern where an agent writes one script instead of
N tool calls.

**Implementation guideline:**

1. **One-shot subcommand, no daemon, no sockets:**
   `agda-explore query <tool> [key=value ...] --graph PATH`. Load the graph,
   build the `Index`, construct the args object from `key=value` pairs, and
   dispatch through the *existing* `ToolRunner` table — zero duplicated query
   logic, and the CLI inherits every future tool automatically.
2. **Graph discovery:** `--graph` explicit, else the daemon's last committed
   union at `cfgOutDir/deps.json` (documented as possibly one rebuild stale),
   else the config-file discovery chain. A sub-second decode of a ~10 MB
   graph is acceptable for one-shot use; do **not** build a live-daemon
   socket protocol until profiling proves the load time hurts.
3. **Output:** default prose (same renderers); `--json` once §5 lands.
4. **Exit codes:** 0 = answered (including "no results" — that is an answer),
   nonzero only for operational failures (bad graph, unknown tool), matching
   the server's philosophy that "not found" is information, not an error.
5. **Explicit non-goal:** the write side stays MCP-only — it is exactly the
   stateful part a one-shot CLI cannot serve, and splitting it would fork the
   zero-axiom contract enforcement.

## 8. Measurement: wire every change to the VerinaAgda A/B

This project owns the rarest asset in the agent-tooling space: a working
189-task A/B benchmark (`~/Repositories/Projects/VerinaAgda`,
`scripts/bench_mcp_ab.sh`) whose harness now demonstrably exercises the MCP
(`--tool-mode bridge`). Every item above is a testable hypothesis, not a
design debate. Discipline:

1. **Metrics per arm:** solve rate; MCP calls per session (parse the headless
   transcripts under `~/.claude/projects/<encoded path>/` — every `tool_use`
   is logged even with `--output-format text`); tokens per solved task; wall
   time. Use `--target proof` (code-target tasks pass single-shot with
   nothing to explore).
2. **Run after each shipped item**, one variable at a time: stdlib overlay
   on/off; hooks on/off (hooks fire in headless runs, so this works —
   drop the hooks into the benchmark project's `.claude/settings.json`);
   `brief` available vs not.
3. **Keep results in-repo** (a `bench/` log with date, commit, arm, metrics)
   so the priority table above gets reordered by data, not taste.
4. **Cheapest first experiment:** Phase-1 hooks (§1) — pure harness change,
   no server code, and it directly probes the routing hypothesis that the
   0-calls-in-262-sessions result exposed.

## Considered and rejected

- **LSP / agda-language-server as the agent interface.** Agent harnesses do
  not reason over LSP; `agda --interaction-json` is already the right
  substrate for goals, and the bridge already owns it.
- **Static greppable artifacts** (TAGS-style index files). Cheap, but stale —
  and silent staleness poisoning agent reasoning is precisely what the
  daemon's freshness machinery exists to prevent.
- **Replacing MCP with a pure CLI.** The write side's value *is* the warm
  stateful session plus enforced contracts; a CLI cannot hold either. The CLI
  (§7) complements the read side only.
- **A permanent second MCP server for stdlib.** Doubles the catalog cost in
  every session; the overlay design (§2) subsumes it. Acceptable only as the
  Phase-0 stopgap.
